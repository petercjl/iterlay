# Tuda 模型设置与山海企业下发需求

## 目标

Tuda 使用山海 OMNI 账号登录。登录后，用户可以在 Tuda 本机配置并使用模型，即使管理员尚未下发任何模型配置。企业日常使用以山海集中管理为主，管理员在山海配置中转站、API Key 和模型授权，员工的 Tuda 自动领取。

Tuda 先定义并验证配置协议、运行时和操作界面。协议通过 Tuda 实测后，山海再按该协议设计管理字段与下发功能。

## 模型类型与选择

| 类型 | 用途 | 选择入口 |
| --- | --- | --- |
| Agent 主模型 | 文本对话、推理、流式回复、工具调用 | 创作助手和画板 Agent 的对话模型菜单 |
| AIGC 图片模型 | 文生图、参考图生成、图片编辑，按模型支持能力提供 | 生图入口或 Agent 发起的图片任务 |
| AIGC 视频模型 | 文生视频、图生视频及模型支持的其他生成方式 | 视频生成入口或 Agent 发起的视频任务 |
| AIGC 语音模型 | 首个场景为文本转语音和旁白，后续可按能力扩展 | 语音生成入口或 Agent 发起的语音任务 |

- 每个类型都能配置多个中转站。同一中转站可以接多个模型，也可以同时提供文本和 AIGC 能力。
- 画板生成节点按「中转站 · 模型」选择。同一个模型 ID 在两个中转站分别显示，作为两项可独立选择的配置。
- Agent 主模型设一个默认项。图片、视频、语音各自维护默认项和本次任务的选择。用户可以用 A 站进行 Agent 对话、B 站生图、C 站生视频。
- 画板侧栏和独立创作助手共用同一个 Agent 默认生图模型。默认值保存模型名称，每个模型可配置多个渠道，按用户设定的顺序调用。手动节点保留所选渠道。
- 切换设置适用于之后发出的请求。Agent 文生图在渠道明确拒绝提交或任务明确失败后尝试下一项。已受理或状态不明时先用原渠道及原任务标识核对，仍无法确认时保留待确认状态。

## 配置结构

| 层级 | 内容 |
| --- | --- |
| 服务连接 | 稳定连接 ID、显示名称、服务商或适配器、Base URL、鉴权方式和 API Key。相同连接的多个模型共用凭据，Key 可独立轮换。 |
| 模型条目 | 连接 ID、服务商模型 ID、显示名称、类型、能力和必要参数。选择项用连接 ID 与模型 ID 定位，按类型使用对应调用入口。 |
| 使用偏好 | Agent 默认主模型、Agent 默认生图模型、每个生图模型的有序渠道列表，以及手动节点选定的服务和模型。 |
| 配置来源 | 本机或山海下发。山海下发附配置版本及当前账号可用的连接和模型范围。 |

- **Agent 主模型**支持 OpenAI Responses、OpenAI Chat Completions 和 Anthropic Messages。配置包含上下文容量和最大输出量，可从内置模板或模型目录获得，也可在自定义配置时填写。
- **AIGC 模型**由服务商适配器定义接口和支持参数。图片按能力提供参考图、编辑、分辨率等选项。视频适配器处理提交、查询、结果下载，以及供应商支持的取消。语音支持模型和音色等参数。
- 内置服务商预置地址和协议或适配器。自定义连接允许填写 Base URL，并选择 Tuda 已支持的协议或适配器。一个中转站同时提供多种协议时，可复用同一份凭据，并为不同用途选定调用方式。
- 配置协议需定义版本、必填字段、默认值、无效配置的报错和旧版本兼容。接口里使用稳定 ID，显示名称修改后仍能保留关联与选择。

## Tuda 本机设置与运行

1. 在「模型设置」中配置服务连接，录入 API Key 并测试连接。
2. 添加或选取该连接的模型，按 Agent 主模型或 AIGC 分类，设置默认项。
3. 在对话和生成入口选择中转站及模型，看到当前使用的来源。测试连接与实际生成分开呈现，明确每项验证到了哪一步。
4. Tuda 主进程按选中的连接解析协议、端点与 Key。Pi SDK 执行当前选定的 Agent 主模型；图片、视频、语音任务由 Tuda 分别交给对应适配器。
5. 本机配置和凭据按当前账号隔离保存，重启后恢复。设置页显示配置状态或掩码。API Key 由主进程安全保存和使用，普通设置回执、日志与调试输出使用脱敏信息。
6. 本机模型设置保存在 Tuda 用户数据目录的 `account-models/<账号标识>/settings.json`。文件记录模型、服务地址、协议和加密凭据。安装包只交付模型配置界面和运行能力，本机设置与测试 Key 不随应用发布。

## 山海企业管理与下发

- 山海在企业范围内管理服务连接、凭据、模型目录及应用授权。管理员可为企业主账号和子账号分别分配可用连接、可用模型及默认项。
- 管理员点「保存并下发」后，山海保存新的授权版本。在线 Tuda 在刷新授权时自动领取，离线设备重新联网后领取。Tuda 按自己的配置协议校验并应用整份更新，用户可在设置中看到来源和下发状态。
- **建议的来源规则**：同一连接和模型同时存在两份配置时，使用企业下发项；未下发的独立模型可用本机配置。企业模型的凭据、授权范围和默认分配在山海管理。员工在可用目录中选择本次要用的模型。
- 企业修改 Key、收回模型或停用账号后，Tuda 在续验时更新访问能力。新版配置只有通过完整校验才启用；异常下发保留错误状态供排查，明确撤权按授权服务结果执行。

## 已核对的开发起点

| 类型 | 当前基础 | 本阶段缺口 |
| --- | --- | --- |
| 文本 | 山海支持给一个账号配置多个文本服务商。Tuda 已有模型选择器和 Pi 调用链路，内部按服务商和模型区分。 | 让本机配置进入同一条调用链路，并在选择器里明确显示中转站名称。 |
| 图片 | Tuda 具备多服务商配置基础，当前企业配置使用一个 ToAPIs 连接和多个授权模型。 | 将多连接模型选择接通本机与企业运行时。 |
| 视频 | 视频生成节点已能保存服务商和模型。 | 山海登录后当前运行配置的视频服务列表为空，需要接通配置、任务提交与恢复。 |
| 语音 | 已有多个旁白 TTS 服务的配置结构，包含端点、模型和音色。 | 山海登录后当前运行配置的语音服务列表为空，需要接通语音生成和选模入口。 |

## 开发顺序与验收

1. **先做 Tuda 文本与生图。** 用山海账号登录，在管理员尚未下发模型的情况下，分别配置两家中转站。用相同模型 ID 测试切换，核对实际请求目标和对应凭据绑定。文本验证流式对话和工具调用，生图验证真实生成和结果回收。
2. **接通视频和语音。** 用同一配置结构完成各自的中转站切换。视频验证提交、查询、结果回收及重启恢复。语音验证模型和音色选择、生成结果以及连接切换。
3. **确定协议后接山海下发。** 用管理员配置与员工领取完成联调，验证现有设置恢复、账号隔离、来源显示、在线与离线刷新、Key 轮换、默认项变化和撤权。
4. **连接测试与真实调用分别记录。** 能列出模型只代表目录可见；文本工具调用、图片生成、视频任务和语音结果分别用各自的真实操作验收。需要产生费用的验证按当次授权执行。

实施前需确认本机与企业配置的来源规则，以及用于实测的中转站和模型清单。第一阶段以 Tuda Mac Dev 为验收入口。
