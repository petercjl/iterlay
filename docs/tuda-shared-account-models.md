# Tuda 公司登录与模型能力

日期：2026-11-12。客户端合同版本：company-v1。公司授权服务与桌面分别验收。

## 职责与配置

“东轩AI授权”提供统一的企业钉钉身份入口。公司授权服务核验组织及稳定员工身份，管理各应用的设备会话、模型目录、文本代理、员工 ToAPIs Key 绑定及 NAS 存储授权。Tuda 使用 `appId=tuda`；其他应用拥有各自独立的设备会话和本地数据。

Tuda 主进程负责浏览器设备授权、模型配置领取、协议适配、Agent 工具循环及 ToAPIs 执行。NAS 负责公共画板、素材、协同状态及业务权限。本机个人空间和公司本地文件夹由桌面管理。

公网账号入口通过部署环境 `TUDA_COMPANY_URL` 或桌面“公司账号服务地址”设置。地址、组织标识、真实凭据和员工绑定记录保存在源码及分发包之外。更换服务地址需要重新授权。

## 登录与自动领取

1. 主进程产生随机 verifier，仅将 SHA-256 哈希交给 `/api/company/v1/auth/start`。
2. 校验授权地址的 HTTPS origin、路径、应用、请求标识及有效期后，用系统浏览器打开。
3. 员工通过企业钉钉身份验证并确认当前应用，主进程按服务间隔轮询并一次性领取设备会话。
4. 调用 `/session` 和 `/bootstrap`，核对 appId、sessionId、organization.id 及 member.id，自动生成模型选项。
5. 有已选存储时进入公司空间；首次使用本地空间时通过原生对话框选择文件夹。用户可以切换个人空间。

会话与原始 bootstrap 通过 Electron safeStorage 加密，保存在应用私有目录。渲染层、CLI 普通回执、素材 URL 和 NAS 只得到必要的公开状态。应用启动及每十五分钟刷新配置；身份撤销、过期或应用访问被拒绝时清除活动凭据并停止受影响操作。NAS 存储权限不足保持公司登录及文本能力。网络错误与撤权分开处理，业务文件保留。

## 文本与 Agent

企业员工完成身份核验后，自动领取云端目录中的三个共享文本模型。模型目录与默认项由服务提供；云端真实上游 Key 留在文本代理中。Tuda 使用自己的设备 token，并发送 `X-Company-App-Id: tuda`。

| protocol | 请求路径 | 桌面行为 |
| --- | --- | --- |
| `anthropic-messages` | `/messages` | 适配系统提示、对话、图片参考和原生 SSE |
| `openai-responses` | `/responses` | 适配 instructions/input、多模态输入和原生 SSE |
| `openai-chat-completions` | `/chat/completions` | 复用现有 Chat Completions 传输 |

Agent 复用画板现有的 Pi Agent 工具循环，通过类型化 JSON 工具决策连接模型与画板操作。协议适配保留工具说明、结果回执和图片参考；主进程执行通过校验的工具调用。公司会话的 Agent 资源目录与应用私有配置按账号隔离。

模型授权属于当前登录账号，切换个人空间或公司空间后仍可使用；画板、素材、历史和对话的存储随当前空间隔离。

## 生图

桌面内置固定依赖 `@petercjl/toapiscli@0.1.1`，通过 Electron 自带 Node 运行 CLI，再由 CLI 通过 ToAPIs MCP 执行。员工无需另行安装全局工具。

`bootstrap.image` 只包含本人已通过稳定身份核验的凭据。姓名、拼音或文件名不能建立授权绑定。未绑定或未核验时显示未获生图授权，文本模型独立可用。

凭据按账号及凭据修订建立独立的 `TOAPISCLI_CONFIG_DIR`，经 CLI `auth import` 免费验证权限。CLI 凭据文件遵循其用户私有文件合同；原始 bootstrap 使用系统加密存储。凭据不放入所选公司文件夹、NAS、提示词或任务记录。

当前批准模型为 `doubao-seedream-5-5`、`gemini-nano-banana-2.1`、`gpt-image-2.6-sunburst`，实际选项取员工授权子集。每次生成一张；参考图保留原字节。画板尺寸映射为模型的分辨率档位与比例，`auto` 使用 2K、1:1；模型不支持的参数明确报错。

桌面关闭 CLI 的独立包自动更新，由桌面版本统一管理依赖。付费任务使用稳定请求身份和私有任务目录；同一请求再次进入适配器时只查询原任务。提交结果不明时保留记录，不自动重新生成。

## 公司存储

### 本地文件夹

选择的文件夹下使用 `.tuda-company/<账号命名空间>` 保存数据，命名空间由账号服务、公司、员工共同派生。画板、素材、生成历史、对话和相关索引使用相同空间路由。个人空间保留自己的原始目录。

本地模式不请求 NAS 存储令牌，也不依赖 NAS 可用性。异步操作固定开始时的账号和目录，避免切换文件夹后写错位置。存储切换分别保留各自画板，上传和合并由显式操作决定。

NAS 的待同步增量保留在原命名空间。切换本地文件夹后可以继续工作，返回同一 NAS 空间后恢复原增量的同步；这些增量不会混入本地画板。

### NAS

桌面按 `bootstrap.storage.scopes` 中已授予的权限通过 `/storage/token` 领取最长五分钟、`audience=tuda-nas` 的独立存储 token；只读员工请求读权限。NAS 使用自己的服务凭据在线调用 `/storage/introspect`，逐次核对有效性、应用、组织、到期时间与操作 scope。

NAS 只接收画板和素材的存储授权，设备/model token 与 ToAPIs Key 不发送到 NAS。公司云端组织 ID 经过验证后映射到现有 NAS 数据空间，保留原画板。Yjs 协同、保存回执、离线待确认增量和本人撤销沿用原有业务层。

模型调用在桌面及公网授权服务完成。生成图片在选择 NAS 时上传到 NAS 素材库，生成节点完成操作通过同一协同领域层回写。只读存储授权不能执行写入。

NAS 部署需要三个私有字段：`TUDA_COMPANY_ORIGIN`、`TUDA_COMPANY_ORGANIZATION_ID`、`TUDA_COMPANY_NAS_SERVICE_TOKEN`。服务凭据仅存在云端与 NAS。启用此模式后，NAS 的模型调用接口不接受存储 token。
