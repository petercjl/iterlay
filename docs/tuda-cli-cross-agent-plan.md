# Tuda CLI 跨 Agent npm 分发计划

日期：2026-11-12。状态：规划，尚未执行本轮实现、其他 Agent 安装或正式发布。

## 目标与范围

将现有 CLI 整理为可由具备命令执行和文件访问能力的任意 Agent 安装、发现、调用和更新的 npm 能力包。沿用现有公开包身份 `@petercjl/tuda`、命令 `tuda`、配套 Skill `using-tuda`，避免新增重复实现。

Codex、codex-own、sealwork 是首批真实验证对象，不是支持白名单。Windows 为正式桌面交付平台，macOS 为本机开发验证平台。Linux 暂仅记录可离线执行的管理命令，不承诺画板运行支持。

本轮以通用 CLI + 可移植 Skill 为入口；专属工具注册适配在明确有必要时单列增量。codex-own 和 sealwork 的真实 Skill 发现与运行机制在实施时核验，不根据名称推断目录或套用其他 Agent 配置。

## 责任与最小缺口

| 层 | 责任 | 本轮最小工作 |
| --- | --- | --- |
| Agent | 理解用户需求、选择素材与工具、编写提示词、判断授权 | 用自然语言调用 Tuda；核实自身 Skill 目录和加载方式 |
| `using-tuda` | 说明能力发现、调用方法、任务恢复和结果验证 | 移除默认宿主与固定调用语法假设，保留通用自然语言入口 |
| npm CLI | 安装、发现、校验、请求本地服务、等待任务、结构化结果 | 统一安装合同、运行时入口和兼容检查，覆盖更新恢复 |
| Tuda 后台 | 画板数据、界面同步、模型配置与调用、持久化任务 | 暴露版本/协议/能力握手，复用业务服务与安全边界 |
| 宿主适配 | 当前宿主目录、元数据、刷新与发现 | generic 默认，确有差异时增加薄适配；不复制业务逻辑 |

外部 Agent 使用 CLI 时由该 Agent 负责理解与提示词，CLI 执行显式请求；无需再次调用应用内对话助手。模型服务凭证仍由 Tuda 管理，安装 npm 包不会授予服务访问，也不会自动提交付费任务。

## 统一安装与运行方式

用户只需给当前 Agent 发送：“安装 @petercjl/tuda，并安装你自己的配套 Skill。”

1. 当前 Agent 检查可用 Node/npm，支持宿主自带运行时，不只依赖系统 PATH。
2. 安装 npm 引导包，通过 capabilities 和 skill source 发现实际合同。
3. 从宿主公开配置或能力发现自己的精确 Skill 目录，显式传给包管理安装器；目录未知时才澄清。
4. 实体安装完整 Skill 与必要运行时，保留来源、版本、摘要及备份回执。
5. 验证 CLI/Skill 一致，再通过宿主原生发现机制确认新会话可以加载。
6. 画板调用前检查桌面/后台、工作区和协议能力；缺少桌面时明确提示先安装，不把 npm 安装成功等同于业务可用。

后续业务与更新统一使用安装回执返回的目标运行时入口，避免更新了 Skill 私有运行时却仍调用旧全局命令。npm 引导包、各宿主运行时和桌面版本分别报告；全局 `tuda` 的来源、桌面启动时的 CLI 安装及 PATH 优先级需统一设计，防止桌面覆盖 npm 安装或反向覆盖。

各 Agent 拥有自己的文件副本和运行时，卸载引导包或另一 Agent 后仍能调用；桌面后台和当前操作系统用户的数据按设计共用。宿主文件隔离不等于各 Agent 自动获得不同画板或模型预算。

## 实施阶段

### P0：完成真实能力与安装入口盘点

- 建立命令清单，区分离线发现、只读、画板写入、文件导出、配置写入、付费提交。
- 核验三个宿主的目录、原生安装入口、Skill 触发方式、命令执行与 Node 环境，形成证据矩阵。
- 梳理 npm CLI、桌面随包 CLI、目标私有运行时的归属、升级与卸载关系。
- 修正多包审计定位，区分合同字段问题、实现问题及未验证项。

验收：命令与依赖清楚，安装及更新使用哪个运行时无歧义；不修改其他 Agent 的安装或配置。

### P1：统一跨 Agent 安装与生命周期

- npm 管理入口作为稳定合同；桌面入口复用该能力，保留可恢复的旧托管安装迁移。
- generic 接受任意有效宿主标识与显式目录；具名适配仅补充已核验的宿主差异。
- 对齐 capabilities、bootstrap 提示、INSTALL/UPDATE、结构化回执和实际参数；明确检查操作副作用。
- 验证重复安装、同版本修复、定向升级、锁目录更新、失败恢复、宿主元数据保留与用户修改保护。
- 保留限时、节流、可关闭的更新检测；安装更新单独依据授权执行。
- 更新 Skill 时加载当前 portable-skill-creator 作为治理入口，保留包内单一来源及构建同步关系。

验收：真实 tarball 安装可完成 CLI + Skill；只影响选定宿主，失败可定位阶段并恢复。

### P2：固化画板与任务合同

- 增加 CLI/桌面版本、协议和能力握手；不支持的操作提前返回准确错误，不能仅凭 status 成功判断兼容。
- 明确当前/指定工作区、默认/指定画板与 Dev/正式目录；保留已有用户设置。
- 统一 JSON、退出码和错误结构，区分连接失败、权限拒绝、能力缺失、已受理、运行中、失败与完成。
- 核对多 Agent 同时操作的保存冲突；付费请求沿用任务 ID 和幂等标识，连接异常后先恢复查询。
- 完成导入、排版、生成结果落板、导出、关闭重开等关键链路；模型验证优先离线响应，真实付费测试另依当次授权。

验收：Agent 可以查询画板、导入素材、排列和导出，桌面显示与持久化一致；生成任务中断后可恢复且不会重复付费提交。

### P4：发布与使用说明

- 复用 `@petercjl/tuda`，不发布平行 CLI 实现；首版先沿用应用/CLI 一致版本策略，协议兼容范围独立声明。
- 暂保留现有单包承载 CLI、Skill 与桌面更新清单的结构。后续确需独立发布 CLI 时，再明确桌面版本映射并迁移发布流程。
- 由 npm-release-kit 检查并复用既有 OIDC 工作流；补齐包级跨平台 QA 与发布依赖门禁。
- 新包若仍不存在，单独完成经授权的一次性初始化，再配置 Trusted Publisher；实际候选发布走 GitHub Actions，预发行用 `next`、稳定版用 `latest`。
- 发布前检查实际 packed 文件、隐私、版本一致性、许可证和安装升级结果；发布后核验公开精确版本、dist-tag 和真实安装入口。
- 使用说明面向当前 Agent，给出最简安装、使用和更新自然语言提示词；宿主专属配置与已测试名单单列。

验收：registry 精确版本可安装，CLI 与 Skill 版本及回执一致，已声明 tested 的宿主均有真实证据，剩余限制明确。

## 顺序与最终交付

按 P0 → P1 → P2 → P3 → P4 推进。当前只做规划；后续代码继续在 `main` 开发，发布和其他 Agent 安装按各自授权范围执行。

交付包含：能力清单、统一 npm CLI 与配套 Skill、兼容/错误/任务合同、tarball 生命周期测试、三个宿主的真实验收矩阵、发布记录和最简使用说明。
