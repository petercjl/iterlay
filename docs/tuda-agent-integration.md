# Tuda Agent 接入与维护

## 当前实现

核验日期：2026-11-12。Tuda 使用官方 Pi SDK 1.5.2；`@earendil-works/pi-coding-agent` 与 `@earendil-works/pi-ai` 精确锁定相同版本。最低 Node 版本为 22.19.0，本机 Electron 42.7.1 内置 Node 24.18.0，满足要求。

创作助手页面和画板右侧对话共用 `electron/agents/tuda-agent.ts` 中的 `TudaAgentService`。两个入口请求同一原生 Agent 路径；每个会话有独立记录，同一个会话 ID 恢复同一份 Pi 上下文。进入不同界面不意味着所有聊天自动合并。

两个 Agent 入口只显示共享的文本模型选择器，默认使用 DashScope DeepSeek；当前配置对应 DeepSeek V4.1 Flash（DashScope）。用户选择其他文本模型后持久保存，两处同步使用。

生图模型由用户通过自然语言指定，图片工具按该模型匹配 ToAPIs 授权配置；未指定时先询问。媒体模型、尺寸等参数由对话传递，两个 Agent 输入区使用文本模型选择器。

右侧始终是 Agent 对话。用户自然表达分析、规划、生成与修改需求；业务动作由工具执行，最终回复用于展示结果。画板上的图片、视频生成节点仍可独立使用。

## 责任与调用链

```text
创作助手页面 / 画板右侧对话
  → 现有 IPC 请求验证、组织身份与员工模型授权
  → TudaAgentService
      → Pi ModelRuntime / createAgentSession
      → 原生模型 Provider
      → Pi SessionManager、上下文压缩、Skill 与扩展
      → 现有 Tuda 画板、图片、视频工具
  → 流式文字、工具回执、交互与最终回复
```

- `electron/agents/coding-runtime.ts`：隔离 SDK 入口和版本相关类型。
- `electron/agents/model-connection.ts`：把 Tuda 模型连接适配为 Pi 原生 Provider。
- `electron/agents/tuda-agent.ts`：恢复会话、注册工具与资源、执行、停止和收尾。
- `electron/providers/text-assistant.ts`：创建已授权模型连接，并把统一对话请求交给共享服务；兼容辅助流程保留各自的结构化输出契约。
- `electron/providers/codex-oauth.ts`：继续由 Tuda 的 OAuth 服务提供凭证与刷新。
- `electron/pi-agent-resources.ts`：发现和加载明确选定的资源。
- `electron/pi-agent-tools.ts`：复用原有画板与媒体工具桥接。

独立桥接仍引用旧作用域的 Pi core 0.73.1，保留为兼容依赖。用户的两个对话入口使用 1.5.2 SDK；后续迁移旧桥接时先检查引用和测试。

## 模型与授权

统一 Agent 原生支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种现有员工模型协议，也提供 Codex OAuth 模型适配。调用模型原生的工具协议，保留工具调用 ID 与结果关系。

员工模型使用现有授权配置，保留公司应用请求头。凭证由 Tuda 授权服务在请求时提供，不复制到 Pi 会话；Codex OAuth 遇到 401 时仍通过 Tuda 刷新后重试一次。Tuda 的模型授权、NAS 存储授权与会话存储继续分别管理。

Agent 执行前为上传参考图准备托管路径，保留编辑主体与来源节点；读取素材时将像素作为视觉内容交给模型。图片和视频仍通过既有 Tuda 工具及媒体服务执行，保留所选模型、参考素材、目标画板、画幅与任务 ID。停止 Agent 会停止本地执行和模型请求，已提交远端媒体任务的取消能力遵循对应媒体服务契约。

## 会话、资源与权限

Agent 数据存于当前 Tuda 用户数据目录下的 `tuda-agent/<空间>/<账号摘要>/`。会话 ID 再映射到独立的 `sessions/<会话摘要>/`；由 Pi 保存 JSONL 会话、工具回执与压缩记录。新一轮重新绑定当前授权和工具回调，再恢复会话，避免保留失效凭证。旧界面历史在该会话首次接入时导入为背景，不重放旧操作。

文件与终端工具沿用用户配置的允许清单。创建 Skill 需要相应写入权限：写入当前 Agent 私有目录的 `skills/<名称>/SKILL.md`，使用有效名称和 frontmatter；下一轮会重新发现和加载该目录。可通过 `/skill:<名称> 任务` 调用。自定义路径和扩展仍从资源设置中明确选用。

支持 `/reload` 重新加载 Skill 和扩展，支持 `/compact` 手动整理上下文；会话较短时提示暂时无需压缩。Pi 自动压缩也已启用。扩展执行代码，普通 Skill 提供方法和指令，二者采用各自的资源契约。

工作区和 Agent 目录中的上下文指令可加载，祖先目录中的开发指令被过滤。工具允许清单控制开放的操作，并不构成操作系统沙箱。

## 更新 Pi SDK

用户说“帮我更新 pi sdk”时，按项目 `AGENTS.md` 第 7 节执行整个流程：

1. 查询 npm `latest`，阅读该发布版本的迁移说明与 SDK 声明；核对 Node 与 Electron 内置 Node。
2. 检查已有修改，备份要改的源码、清单与锁文件，保留用户数据。
3. 用 pnpm 精确升级官方 SDK 与直接使用的配套包，保持可复现的锁文件。
4. 在适配边界完成迁移，核对原生模型协议、会话和工具事件、Skill、扩展及取消行为。
5. 运行相关测试、类型检查和构建，启动固定位置的唯一 Mac Dev，并实际验证两处入口。
6. 记录版本、结果、兼容依赖和未验证的平台。正式发布按独立发布流程执行。

SDK 声明与示例以本地安装版本为准；官方 main 分支文档可能领先已发布版本。

## 首页、主动对话与 Skill 管理

普通启动进入画板库首页。进入画板由用户操作或显式 CLI/深链触发，应用启动不加载上次画板内容。

Agent 在用户发送消息后执行。推荐短句、独立意图建议服务、输入停顿与新增引用自动分析已移出应用运行路径；界面和设置不提供这些入口。登录、文本模型授权、用户主动调用的 Agent 与媒体工具继续使用现有契约。

创作助手和画板对话的输入区提供 **Skill** 菜单：可选择一个 Skill 用于本轮请求，也可打开 **Skill 看板**。看板列出内置创作指南、Tuda 本地 Skill 和发现的共享 Skill，支持查看内容、使用和刷新。用户创建的 Skill 保存在 `~/.tuda/dev/tuda-agent/<space>/<account-hash>/skills/<name>/SKILL.md`（Dev）或 `~/.tuda/stable/tuda-agent/<space>/<account-hash>/skills/<name>/SKILL.md`（正式版）；看板可展开查看当前账号的实际目录。通过对话创建需要启用对应文件写入权限，SDK 在下一轮重新加载本地目录。

选择结果通过 `selectedSkillPath` 随请求发送，主进程按当前账号与空间重新发现并验证路径，再加入本轮资源。Pi SDK 使用原生 `/skill:<name>` 展开完整内容，保留相对引用目录；路径失效或同名覆盖导致所选文件未加载时返回明确错误。

只有 Tuda 私有 `skills` 下的直接 Skill 文件夹可在看板删除。点击删除后弹出原生确认框，默认取消；确认后整个 Skill 文件夹移入系统废纸篓。共享目录、安装包及符号链接不会通过此删除入口处理。取消不修改文件，删除后刷新清单并取消已删除的选择。

验证：首页与两入口通过 Mac Dev 桌面验证；自动化测试覆盖 Skill 原生展开、删除取消、目录边界和符号链接保护。当前增量回归共 198 项通过；Skill 相关最终增量 14 项复核通过。Mac Dev 实际验证了内置清单、显式选择、本地测试 Skill 发现、删除取消和确认后移入系统废纸篓。临时测试 Skill 已清理，废纸篓保留可恢复副本。启动日志中推荐请求与文本模型错误均为 0；已有 NAS 维护警告属于独立存储维护问题，不等同于模型加载失败。


## Skill 分类与持久目录

对话菜单默认展示用户 Skill，系统 Skill 收在独立子菜单。未指定 Skill 时用户可直接描述需求，由 Pi 基于已加载的 Skill 说明按语义触发；手动指定通过原生 Skill 命令加载对应文件，菜单提供“取消指定”。看板通过“用户 Skill / 系统 Skill”切换列表，系统分类来自应用声明的内置指南，独立于文件来源及删除权限。

Pi SDK 的配置、模型注册文件、会话、扩展、安装包与用户 Skill 根目录固定在用户主目录的 `.tuda/dev/tuda-agent/` 或 `.tuda/stable/tuda-agent/` 下，再按空间与账号哈希隔离；系统指南覆盖文件、演进记录与 Agent 日志也位于相同持久根目录。画板、公司登录凭证及应用通用设置继续遵循各自现有存储契约。

首次迁移复制旧目录中的缺失文件，保留目标目录已有内容和原始来源，每个来源只导入一次。复制后的 Pi 路径配置会转换到新位置并保留恢复副本；旧项目目录保留为恢复点，后续启动不重新导入旧内容。Dev 与正式版通过目录隔离，Windows 使用当前用户主目录解析相同结构。

本轮验证（2026-11-12）：55 项相关测试通过，前端构建与主进程类型检查通过。Mac Dev 实际确认了用户 Skill 默认入口、系统 Skill 子菜单、显式指定与取消指定、看板分类切换；看板显示当前目录位于 `~/.tuda/dev/tuda-agent/` 下。现有 6 个 SDK 数据文件复制后与源文件内容一致，源文件保留。正式 Windows 目录解析沿用当前用户主目录，本轮未进行 Windows 运行验收。


## Skill 文件夹、收藏与区域看板

Skill 看板覆盖所属对话区域，保留应用左侧导航的视觉位置。搜索支持名称、描述与所属分类路径；用户 Skill 可创建嵌套文件夹、重命名和调整所属分类。分类为本地管理信息，保持 Skill 文件和 SDK 引用路径稳定。移除文件夹及其子分类前二次确认，Skill 文件与收藏保留，所属 Skill 回到全部用户 Skill。

收藏区可收集系统和用户 Skill，卡片星标可添加和取消收藏；收藏同时出现在两个对话入口的 Skill 快速选择菜单。分类和收藏保存在当前账号、空间的 Agent 目录 `skill-library.json`，通过主进程校验与串行原子写入持久保存；系统 Skill 不参与用户文件夹分类。既有 Skill 文件删除仍使用原生二次确认和废纸篓恢复流程。

本轮看板验证：51 项相关测试覆盖分类与收藏的持久化、并发更新、嵌套文件夹、删除分类保留 Skill、损坏配置保护、搜索、收藏筛选、快速使用与卡片分类。Mac Dev 实测对话区域全屏布局、系统 Skill 搜索、收藏同步到选择菜单、文件夹创建和确认移除；测试收藏及临时分类已恢复为空，Skill 文件未改动。
