# Tuda 公司登录与 Agent 工具接入

## 山海企业账号部署

在 Tuda 的部署配置中设置 `omniOrigin`，开发时可用 `TUDA_OMNI_URL`。员工在 Tuda 点击「前往山海授权登录」，山海 OMNI 桌面端使用当前企业账号显示 Tuda 授权确认。未登录时，先在山海登录，再确认授权。授权完成后，Tuda 领取独立的设备会话并回到前台。

Tuda Dev 通过 `shanhai-omni-dev://authorize` 打开山海 Dev，正式安装版通过 `shanhai-omni://authorize` 打开山海正式版。账号服务地址由部署配置指定。链接只传递本次申请编号。系统无法打开山海桌面端时，Tuda 打开浏览器授权页。启动和续验由主进程向山海领取应用权限、模型目录和凭据。默认文本模型取山海下发配置，员工已保存的选择在仍有效时优先。

Tuda 使用山海 OMNI 授权登录。对服务端已完成身份绑定的员工，山海会话返回原组织和成员标识及 `legacyWorkspace: true`，Tuda 使用 `legacyWorkspaceOrigin`（缺省时取 `accountOrigin`）定位原工作区和账号设置。旧 NAS 接入山海授权与内省时沿用原组织和成员映射。

企业画板和图片跟随山海中企业选定的托管、NAS 或自购服务器。管理员为相应来源登记 Tuda 企业服务地址，Tuda 在 `bootstrap.storage` 领取来源和访问范围，以相同来源和地址请求短时存储授权。桌面通过 Tuda 企业服务读写画板和图片，连接目标由山海管理。变更企业存储来源后，桌面断开旧连接并提示重新连接，原存储中的数据及待同步修改保留在原处。无企业存储授权时从本地空间开始。个人工作区的画板和图片保存在当前电脑。

## 身份与能力

山海按企业及成员的稳定标识核验账号，并为 Tuda 签发独立设备会话。应用启动时在线验证会话，准备工作区和工具后进入主页。退出、到期或撤销应用授权后返回登录页。

登录后自动获取员工文本模型目录、默认模型及直连配置。公司服务负责身份和权限验证，桌面直接调用获授权的模型服务商；共享文本 Key 随独立 Tuda 会话使用系统安全存储加密保存。真实 Key 由主进程在已验证服务商请求中注入，普通设置、Pi SDK 与渲染层只获得必要的元信息或占位标识。已绑定 ToAPIs 的员工自动导入其个人凭据，凭据保存在私有账号目录，不进入提示词、Skill 或 NAS。

现有会话启动时自动获取 company-v1 的 `/direct-models`（contract=2、transport=direct），验证 appId、sessionId、subject、配置摘要、服务商端点和模型目录。每 120 秒续验，正向授权租约最长 300 秒；退出、撤权、到期和模型配置变化时停止受影响的文本流。断网仅沿用尚未到期的在线租约，启动恢复不沿用上一次运行的租约。配置更新在校验和加密保存后供下一轮调用使用。

未配置生图 Key 的员工仍可登录并使用已授权文本模型。生图工具明确提示当前员工未获生图授权；管理员配置 Key 后刷新公司模型授权即可更新能力。

首页、画板和创作助手共用左下角的账号入口。员工可通过该入口刷新山海账号与授权、设置本机 Tuda 昵称或退出。留空时使用账号姓名。

## Pi Agent 与 ToAPIs

登录验证后自动调用 npm 锁定版本 `@petercjl/toapiscli` 自带的 Skill 管理入口，将规范 Skill 和独立 CLI 运行时安装到当前账号/空间 Pi 配置下的 `system-skills/toapiscli`。Dev 根目录为 `~/.tuda/dev`，正式版为 `~/.tuda/stable`。安装无须员工图片 Key，也不接触其他 Agent 的安装。

Tuda 管理工具版本，随应用依赖升级；CLI 安装器负责检测版本、保留冲突文件和验证运行时。该 Skill 注册为系统 Skill。用户 Skill 保持独立。

创作助手与画板对话共用这些资源。图片生成、编辑和状态查询使用 Tuda 内置工具，由主进程注入凭据并管理任务幂等、产物导入和授权范围。当前授权模型通过每轮上下文提供，用户自然指定模型，未指定时由 Agent 询问。

## 安全边界

`CompanyLoginGate` 在验证前不挂载工作区；主进程公司登录策略同步拒绝未登录业务 IPC，包括个人存储、Pi 工具和模型调用。登录、更新及必要窗口生命周期操作仍可用。共享服务负责跨组织、应用、会话撤销和员工授权校验。

## NAS 画板导航回归（2026-11-13）
