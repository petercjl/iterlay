# Tuda 统一 Pi Agent：调研与接入设计

核对日期：2026-11-12。本文区分代码现状、官方能力与建议方案；未实施项不视为已支持。

## 产品目标

Tuda 使用一个基于 Pi harness 的 Agent 实现。创作助手页面和画板右侧对话共用模型接入、工具、Skill、权限、执行事件和会话服务。入口提供当前画板、选中素材和用户消息等上下文。

同一会话可以在两个入口继续，保持消息和执行状态一致；不同会话、账号及空间分别隔离。一个 Agent 实现可以管理多个独立会话，不把所有用户任务混成一个全局对话。画板切换时显式更新目标上下文，执行中的任务保留提交时的目标画板。

## Pi 的定位

Pi 是可扩展的 Agent harness。其模型接入、执行循环与完整会话 SDK 分层提供：

| 组件 | 职责 | Tuda 的使用方式 |
| --- | --- | --- |
| pi-ai | 模型与 Provider 协议 | 对接员工获授权的文本、视觉模型 |
| pi-agent-core | 模型和工具之间的执行循环、状态与事件 | 由上层 SDK 使用，避免再自建一套循环 |
| pi-coding-agent | 会话、资源、工具、扩展等完整 SDK 与 CLI | 嵌入 Tuda，作为统一运行时 |

它们属于不同层次，不是需要用户选择的三种业务 Agent。coding-agent 的名称和默认工具面向编程，但 SDK 支持自定义系统指令、工具及资源，可以承载媒体创作任务。Tuda 的媒体分析与生成能力仍由所选模型和接入工具共同决定。

## Tuda 代码现状

1. `package.json` 已安装并锁定 `@earendil-works/pi-coding-agent`、`@earendil-works/pi-ai` 0.84.2；另有 `@mariozechner/pi-agent-core`、`@mariozechner/pi-ai` 0.73.1。两组依赖均有引用，不能直接删除旧包。
2. `electron/agents/coding-runtime.ts` 封装新 SDK 的导出；`electron/providers/text-assistant.ts` 实际调用 `createAgentSession`，并注册 Tuda 工具和交互扩展。这是实际的 Pi 执行接入。
3. `src/components/workbench/CreationAssistantPage.tsx` 请求 `agentMode: true`、`creationWorkflow: true`。该路径允许自然语言结束本轮；旧画板助手路径仍要求 `finish_assistant_result` 结构化收尾。
4. 当前模型连接使用 `fauxProvider` 转接真实 `TextTransport`；`createCodingAgentDecisionFactory` 和 `electron/agents/completion-protocol.ts` 要求模型输出文本 JSON，再解析成 Pi 工具调用。真实模型仍被调用，但并非直接沿用 Pi Provider 的原生工具调用通道。文本 JSON 解析与纠正是额外故障点。
5. 每次请求创建 `SessionManager.inMemory()`，把传入历史包装进任务消息。界面已有历史不等于完整 Pi 会话树、工具回执和上下文压缩状态已经持久恢复。
6. `electron/pi-agent-resources.ts` 支持 Skill、扩展的发现及选定资源加载。发现清单与实际加载清单不同；当前 loader 通过明确路径加载。
7. `electron/storage/settings-store.ts` 的文件工具默认是 `read/grep/find/ls`，可配置 `write/edit/bash`。可执行范围由配置和工具实现决定。工具开关本身不等同于操作系统沙箱。
8. `electron/workspace-tools.ts` 已定义画板、图片生成与编辑、视频生成及任务状态操作。视频内容理解是否具备完整抽帧、采样、视觉分析链路，需要另做能力验证，不能由存在视频生成工具推断。
9. `electron/mastergo-bridge.ts` 仍引用旧 core 运行时。统一用户对话后，应逐项审计其他桥接调用的职责；内部执行器不应发展成入口各自维护的第二套用户 Agent。

本次只读取代码与官方资料并形成设计，没有运行付费媒体任务，也没有修改运行时代码。

## 最小接入边界

- **Tuda 界面**：展示会话、引用素材、选择目标画板与模型；展示执行事件，提交用户消息。
- **统一 Agent 服务**：维护会话 ID、生命周期、Pi SDK、消息流、停止与追加指令、持久化、账号和空间隔离。
- **应用 Skill**：表达创作方法、参考素材使用、生成提示词与质量验收。Skill 支持按需加载和版本管理。
- **能力工具**：执行画板操作、素材读取、图片/视频任务、状态查询、文件与命令操作；返回真实结果和任务 ID。
- **模型与授权适配**：获取已有员工模型授权并适配 Provider；凭证留在受保护的服务端/本地凭证存储，界面和会话只使用引用。

当前最小缺口是统一两个入口的会话/执行契约，以及验证原生工具调用的模型适配。无需另装一个独立 Pi 桌面软件，也无需借用 Codex 或 OpenCode 的会话和私有配置。

## 建议实施顺序

以下是有依赖关系的工作清单，可以在一次改造中连续完成。

1. 定义唯一 `TudaAgentService` 契约：创建、打开、发送、订阅、停止、追加指令、关闭；请求包含账号、空间、会话和目标画板标识。锁定 SDK 版本并隔离版本相关类型。
2. 创作助手与右侧对话接入同一服务。移除模式切换和界面根据最终回复自动生成的逻辑；图片、视频及画板动作由工具执行，最终回复展示事实。
3. 按已授权文本 Provider 验证 Pi 原生工具调用。优先支持真实使用的协议，验证流式工具参数、视觉输入和错误传播。旧文本 JSON 路径只有在兼容性明确需要时才保留，并记录实际使用的适配方式。
4. 建立可恢复会话存储，保留工具回执、任务 ID、压缩记录和模型信息。界面历史与运行时记录分清权威来源；迁移旧对话时记录能力边界。
5. 统一工具注册、权限和执行空间。媒体工具复用现有任务服务，检查重复提交和恢复；停止本地等待与取消远端媒体任务分别表达。
6. 建立 Tuda 自有 Skill 根目录和管理流程：创建到新路径、校验格式及名称、加载、更新、重新加载、禁用、失败恢复。写入已有 Skill 需要恢复点；受信扩展的执行权限与普通 Skill 文本区别管理。
7. 接入结构化日志和回归任务，再针对真实失败调优提示词、上下文、工具描述、模型和资源加载。

## 图片与视频的能力组成

图片分析需要视觉模型收到真实图片内容；托管路径用于定位素材，不能替代视觉输入。图片生成和编辑通过独立工具调用既有媒体服务，并把可核验的结果写入目标画板。

视频分析需要确定支持方式：模型原生视频输入，或抽帧/镜头采样配合音频、字幕分析。视频生成通过对应工具提交异步任务、跟踪结果、恢复状态。工具声明支持的参数和所选模型能力必须匹配。

付费任务须继承明确授权；网络中断后先查询既有任务，不能因 Agent 重跑而重复付费。参考素材、所选模型和输出位置在整个调用链中保持一致。

## 调优与验收

这里的调优首先指 harness、提示词、Skill、工具和上下文调优；模型权重微调属于另外的工作。

| 验收任务 | 核心证据 |
| --- | --- |
| 两个入口继续同一会话 | 消息、执行事件和任务 ID 一致，不重复执行 |
| 只讨论方案 | 有回复，没有创建媒体任务或自动生成弹窗 |
| 分析选中图片 | 模型收到对应图片，结论能回溯到素材 |
| 已授权生成、编辑及视频任务 | 引用、模型、画幅、数量、目标画板正确，完成状态有回执 |
| 中断与重启 | 恢复既有任务，不重复提交付费请求 |
| 创建并使用 Skill | 写入、校验、重新加载后可在新会话实际调用 |
| 工具失败与权限边界 | 如实报告，不能把失败显示为完成；账号与空间无串用 |
| 长对话 | 压缩前后保留关键用户要求、参考素材与未完成任务 |
